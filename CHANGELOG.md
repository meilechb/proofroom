# Changelog

Newest first. One line per meaningful change; phase numbers refer to docs/BUILD-PLAN.md.

## Unreleased

- Phase 18 (Lightroom plugin, 18.12-18.22): a Lightroom Classic publish plugin (placeholder "Proofroom") adapted from the proven single-studio plugin to the new API — token entry with a Test-connection check and version-minimum prompt, per-collection client picker (search or create) and proofs/finals type, an upload loop over begin + PUT, republish-in-place and delete, client favorites and comments synced into Lightroom's ratings and Comments panel, favorite and gallery-name keywording, and open-gallery/open-studio links. Served login-gated from /api/plugin/download, zipped on the fly with the studio's site URL stamped in; a standalone build-plugin script and a manual test script (docs/LIGHTROOM-TESTING.md) round it out.
- Phase 18 (Lightroom API, 18.1-18.11): a bearer-token API for the plugin — withApi wraps every route (token to studio, 120/min per-token rate limit, read-only block on writes, JSON errors with codes, X-LR-Api-Version header); ping, client search/create, gallery list/create, photo begin/complete/replace/delete (same direct-to-Blob token flow as the web, with sha256 dedup), gallery favorites-and-comments feedback since a timestamp, and publish/unpublish. Documented in docs/LIGHTROOM-API.md with a v1 changelog; helper and version tests added.
- Phase 17 complete (notifications and tests, 17.5/17.9): per-user notification preferences (new inquiry, new note, payment received, booking made, daily digest) stored per membership and edited on the account page, with a notifiableMembers helper for send sites; tests assert the role gates the settings actions rely on (member cannot invite, admin cannot delete or transfer), timezone validation and notification defaults.
- Phase 17 (Lightroom, data, audit, 17.6-17.8): a Lightroom tab manages connection tokens (create shows the token once, list with last-used, revoke) with plugin download and guide links; a Data tab exports the studio's records as a zip of JSON plus a clients CSV and, for the owner, deletes the studio behind a typed-name confirmation that cancels the subscription, disconnects Stripe and soft-deletes the row; an activity-log viewer filters the audit trail by person, action and date.
- Phase 17 (team, 17.4): the Team settings tab lists members with role and last sign-in, invites by email with a role (emailing the existing accept-invitation link), changes roles, removes members, lists pending invites with resend and revoke, and lets the owner transfer ownership. The owner cannot be removed or demoted except by transfer; you cannot remove yourself.
- Phase 17 (profile and branding, 17.2-17.3): the Settings profile edits studio name, legal name, contact email, phone, timezone (IANA-validated), currency, address and business hours; a branding tab picks a logo and favicon from the asset library and sets the brand color, writing the logo through to the studio header and app emails.
- Phase 16 (timeline, tests, docs, 16.9/16.19/16.20): each automatic email a client receives is recorded on their timeline; tests cover the Svix webhook signature (valid, tampered, stale, multi-signature), automation settings defaults and clamping, and template override/render; the SETUP guide's Resend section is written in full (API key, platform domain, webhook and signature, per-studio domains, plan sizing, local testing). Platform admin domain-usage (16.18) lands with Phase 19.
- Phase 16 (sending domain, 16.11-16.17): /studio/settings/email-domain adds a studio's own sending domain through Resend — explanation, a prefilled subdomain input, the DNS records to create with copy buttons and per-record status, a check-now button, a from-address editor, an optional DMARC helper, a verified-state test send, and remove. Pending domains re-check every 15 minutes as well as daily.
- Phase 16 (automations, 16.7-16.8, 16.10): /studio/emails/automations toggles and times each automatic email (balance reminder, gallery expiring, thank-you, review request, session reminder, unanswered-note nudge) with a pause-all switch for vacations; a daily runner claims each due target in automation_sends before sending so it fires at most once, skips paused or disabled rules, and renders the studio's own template wording with resolved links.
- Phase 16 (log, webhook, suppressions, 16.4-16.6): /studio/emails/log lists every sent email with delivery status, filters by status and template and a recipient search, a detail drawer showing the delivery timeline and stored body, and resend; a Resend webhook at /api/resend/webhook verifies the Svix signature (manual HMAC per the docs), mirrors delivered/opened/clicked/bounced/complained into the log, suppresses hard bounces and complaints, and forwards domain events to the sending-domain record; a suppression page lists blocked addresses with add and remove. Email bodies are now stored on send.
- Phase 16 (email templates, 16.1-16.3): /studio/emails lists every client email with its trigger and a customized/automatic badge; a per-template editor edits subject, body and button label with one-click variable insertion, a live preview filled with sample data, a test send to yourself and reset-to-default; a sender panel sets the from-name and shows the from-address (your verified domain or the shared address) and reply-to.
- Phase 15 complete (15.6, 15.8, 15.9): import portfolio photos from a finished gallery — only galleries whose client agreed to portfolio use in their agreement are offered — copying the chosen photos into the public asset store and adding them to the portfolio; a daily orphan-blob cleanup that deletes blobs older than seven days with no database row (age-guarded, per-store, bounded per run); and tests for folder validation, the where-used delete block and storage-delta accounting, plus the custom-domain DNS record builder.
- Phase 15 (portfolio, 15.5): /studio/portfolio curates the public portfolio from the asset library — add photos through a multi-select dialog, drag to reorder, edit each photo's category (with autocomplete) and caption, toggle featured and published, remove, and bulk-rename a category. Removing a portfolio item never deletes the underlying asset.
- Phase 14 (image picker, 14.18.3): the website editor now picks section images from the asset library — hero, intro, closing-CTA background and the About portrait — with a searchable thumbnail dialog, a current-selection preview and a nudge to add alt text (edited on the asset so it stays consistent). Alt text lives with the asset, not the section.
- Phase 15 (asset library): /studio/assets with multi-file direct-to-Blob upload to the public store, three sizes generated on upload (original, 1600px web, 480px thumb), a thumbnail grid with search (name, tag, alt), folder filter and sort; a detail drawer for alt text, tags, folder and a where-used check that blocks deletion when an asset is on the site, in the portfolio or used as the logo; multi-select with bulk move-to-folder and bulk delete; storage total shown on the page and kept in the studio's usage counter.
